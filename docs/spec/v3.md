# Etch v3 specification (draft)

**Status: draft.** Started from the grilling of 2 November 2026, whose first
question was how well Etch shows *every* view of the game. It holds what v3 is
for, the coverage survey that measures it, the targets and the work the first
survey found; since 9 November 2026 also Compare with Live Game, the release
line and the scope (eu4-engine-lab#17). Everything else Etch does stays as the
[v2 specification](v2.md) says; its open points stay in
[after-v2.md](after-v2.md) until this draft takes them up.

## 1. Target

Etch v3 is the release a mod author can trust for **any** window of vanilla and
Anbennar, and for a window of their own mod: the outline draws every widget
where the game draws it, the preview shows and hides what the game would, and a
live snapshot puts into the preview everything the game showed. v2 proved this
for the 16 views of the precision corpus; v3 proves it for every view a player
can open, and says how far the proof carries to windows nobody measured.

## 2. The coverage survey

Decided in the grilling (questions Q1–Q16); the method is
[docs/coverage.md](../coverage.md):

- **A view** is a state of the screen a player opens (Q1), told apart by its
  signature; every top-level `.gui` window is a view's root, inside a view, or
  not reached, with the reason.
- **Playsets** (Q2, Q16): vanilla and Anbennar alone are crawled; Bigger UI
  V1.37 is the holdout, measured once on vanilla's views before any fix and
  reported apart. The P2K playsets follow for the views their mods change.
- **Finding the views** (Q6, Q12–Q14): a crawler clicks, breadth first and three
  steps deep, every shown and enabled button and check box (first rows only),
  the survey's keys and provinces of each kind, keeps the game's state with a
  fingerprint and fresh starts, and never confirms an action. Each view's
  recipe is checked by capturing it from a fresh start.
- **Resolutions** (Q5): 1920×1080 for every view; 1280×720 for the views with a
  small variant.
- **Game calls** (Q4, Q7): allowed in the survey, never in the corpus, and marked
  per view. The first survey made none, so it did not open other countries'
  views.
- **Measures** (Q3, Q8–Q10, Q15): the outline offline (geometry and visibility),
  the preview from the live snapshot (geometry, visibility, texts), pixels by
  the corpus comparison (reported), and constructs with a window's confidence.
  The outline offline with the profiles (measure 4) is taken with the
  snapshot's texts as sample data too, the variant **Compare with Live Game**
  takes (section 4), so the survey and the command report the same figures.
- **Results** (Q11): [docs/coverage-results.md](../coverage-results.md), one
  issue per class of failure, fixes by their own pull requests.

What v3's survey still has to reach, decided on 9 November 2026 (eu4-engine-lab#17,
Q6):

- **The menus to the end**: every window of the main menu and the lobby the
  crawler can open without leaving the menu (the crawls of 3 November stopped
  part way).
- **Views behind a confirmation** up to and including the dialog, never
  confirming it: the dialog is a view, what it would do is not.
- **Views that depend on the country** (the emperor's, the Pope's controller's,
  a colonial nation's) through a console `tag` on a private copy of the save,
  each such view marked as taken with a game call.
- **The gate takes the views of profiled windows only**; every other view is
  reported, not gated (section 3).

## 3. Targets and the release gate

| Measure | Target | Gates 3.0.0 |
| --- | --- | --- |
| Outline geometry, every surveyed view | 100 % of compared rects exact | yes, for the views of a profiled window; reported for the rest |
| Visibility, views of a profiled window, from the live snapshot | 100 % | yes |
| Live snapshot texts, profiled windows | 100 % of the texts the game shows | yes |
| Pixels of surveyed views | reported | no; the precision corpus keeps its gate (ADR 0002) |
| Holdout | reported apart, once | no |
| Windows not reached | each with a reason; confidence reported | no |

A difference is a bug or a known deviation with an issue and the maintainer's
consent, never a tolerance, as in ADR 0002. The gate is unchanged by the
decisions of 9 November 2026 (eu4-engine-lab#17, Q5): views of windows without a
profile, the views behind a confirmation and the views of other countries are
reported, and enter the gate once their window has a profile.

## 4. Compare with Live Game

Decided on 9 November 2026 (eu4-engine-lab#17, Q1–Q3 and Q8–Q14). A command for
the mod author's own windows: **Etch: Compare with Live Game** compares the
**offline preview** of the previewed window with a live snapshot of the same
window, and lists each **live difference** in Problems, with the widget's file
and line.

### What it compares

- **The source** (Q1) is a live snapshot that Etch's own plugin takes in the
  private install (Anvil with `tongs.ui` in the process, protocol 2, the
  `snapshot` request), as the preview's snapshots are taken. Not Tongs' pipe or
  its MCP server, which the private install leaves off on purpose, and not the
  survey's captures, which exist for vanilla and Anbennar only: the command is
  for windows of the author's mod.
- **Against what** (Q2, Q8): the offline preview of the window: the outline with
  the window's profile where it has one, the profile's selectors set to the
  values that fit the snapshot, and the snapshot's texts and list rows as sample
  data. Not the snapshot's positions, visibility or toggles from the game: those
  are what is compared. A preview built from the snapshot is not compared, as it
  would compare the snapshot with itself. The texts' content is not compared
  either: the snapshot's texts are put in so that boxes the game sizes to their
  text have the game's size.
- **The measures** are the survey's (`outlineGeometry`, `visibilityAgreement`
  in `@etch/core`), over a plan built from the snapshot as the survey builds one
  from a capture; measure 4 of the survey is taken with the same texts
  ([coverage.md](../coverage.md)), so the two cannot drift apart. The functions
  are shared, not copied.
- **No pixels** (Q3): the snapshot has none; pixels stay with the precision
  corpus and the survey (ADR 0002).
- **A window without a profile** (Q9): geometry widget by widget, as for a
  profiled window. Visibility is one entry for the whole window ("the game
  hides N widgets that the preview draws"), since without a profile the preview
  draws everything and a list of every hidden widget would say nothing new; the
  entry offers **Save as view** (a view of the mod's own profile from what the
  game showed) and **Open profile**.

### When it runs

- **Triggered** (Q10) by the command, and by a button beside "Profile differs in
  N paths" in `Data ▾`. When the game shows the window, Etch takes a fresh
  snapshot. Otherwise it uses the stored one, only when its SHA-256 of the
  window's winning `.gui` file is the file's hash now; with another hash it
  refuses and says to open the window in the game. Comparing on every reload is
  later work.
- **In Problems** (Q11): a collection of its own, `etch-live-compare`, at
  severity Information, as a difference is mostly a flaw of the preview, not of
  the author's file. A window's entries go when the next Compare of that window
  runs or when its file changes, not when the game stops.

### Report to Etch

Each difference offers **Report to Etch** (Q12): an issue of
`happy-dwarf-team/etch` filled in beforehand with the widget's path, the kind
of difference, both rects, the visibility, the versions of Etch, Anvil and
Tongs and the resolution. No files and no texts of the mod go in it. The author
sends it from the browser, after seeing what it holds. This is the one exception
to v2's rule that a snapshot is never shared or exported (v2 section 7): the
author sends a few fields of it, by hand.

### Done for 2.7.0

- On the survey's captures, the command's comparison gives the same figures as
  the survey's measure 4 with the snapshot's texts (a test over stored
  captures).
- One run in the lab under its game lock: a window of the demo mod and two
  vanilla windows with a profile.
- The province view takes under 1 s from the command to Problems.

## 5. What the first survey found

The first run, 2–3 November 2026 (EU4 1.37.5, `eu4.exe` 9AD3EFE1…, Tongs
0.23.0, UI scale 1), in full in
[docs/coverage-results.md](../coverage-results.md):

- **Found:** 73 views in vanilla and 52 in Anbennar alone from the save, 4 each
  from the main menu; no game call, no change to the save, the settings put
  back after every start. The fingerprint caught two clicks that changed the
  game (Anbennar's single unit panel builds a regiment at once), and the
  settings check the message list's toggle, which writes `settings.txt`; both
  are `never` patterns now, with the minimap's buttons, whose map modes Escape
  does not undo.
- **Captured:** 54 vanilla, 51 Anbennar and 54 Bigger UI views at 1920×1080,
  and the 37 views per playset with a small variant at 1280×720 (262 captures,
  each from a fresh start of its recipe). Views whose window remembers its last
  tab, and views that Escape does not close, are captured as a fresh game opens
  them.

| 1920×1080 | Outline rects | Live rects | Live visibility | Live texts, profiled windows | Live texts, all |
| --- | --- | --- | --- | --- | --- |
| vanilla | 75.7 % | 77.9 % | 95.8 % | 98.8 % | 25.2 % |
| Anbennar alone | 85.7 % | 87.5 % | 87.4 % | 98.9 % | 35.4 % |
| Bigger UI (holdout) | 75.7 % | 77.9 % | 95.9 % | 98.8 % | 24.6 % |

Against the 100 % the corpus shows for its 16 views, the survey says what
those views hide, and where to work:

1. **What the game's code moves** keeps its `.gui` position in the outline and
   in the preview from a snapshot (the corpus's `codeMoved` patterns hide it):
   the province view's top section, the institutions, the subjects' panels,
   the menu bar's buttons and a dozen texts and icons that move with their
   content ([etch#253](https://github.com/happy-dwarf-team/etch/issues/253)).
2. **The military tab** is 16 px higher than the game shows it, with all its
   111 widgets ([etch#254](https://github.com/happy-dwarf-team/etch/issues/254)).
3. **A window without a profile takes nothing from a live snapshot**: three
   texts in four the game shows are not taken, and the text boxes the game
   sizes to their text keep their `.gui` size
   ([etch#255](https://github.com/happy-dwarf-team/etch/issues/255)).
4. **What the game builds from other definitions or draws with a sprite it
   sets** is missing from the outline or has another size
   ([etch#256](https://github.com/happy-dwarf-team/etch/issues/256)).
5. **The profiles** draw the province view's building slots off by the slots
   the game hides, miss the ledger's sort buttons, and have selectors no value
   fits to the snapshot
   ([etch#257](https://github.com/happy-dwarf-team/etch/issues/257)).
6. **The survey itself** does not yet measure pixels with the game's content,
   reach behind the main menu, open other countries' views or say why a window
   is not reached ([etch#258](https://github.com/happy-dwarf-team/etch/issues/258)).

**The holdout carries over.** Bigger UI V1.37, which changes 21 `.gui` files
and which Etch was never tuned on, measures the same as vanilla to the tenth
of a per cent: where the mod changes a window, the outline follows it as the
game does (`vanilla-save-s14`: 60 of 60 rects exact in both, with 176 rects
the mod moved). What fails in it fails in vanilla too.

**The confidence of windows no survey reached is low** (2 of 513 vanilla
windows at 50 % or more): with the text boxes and window positions above
failing in more than 5 % of their widgets, their constructs are not confirmed.
It rises with the fixes of 1–5, which a second run of the survey measures.

- **Visibility with profiles** (84.2 % in vanilla, 73.8 % in Anbennar alone):

- **Sizes the code sets** (etch#256's second half, etch#264's rest): sprites
  the code picks, and a few text boxes that break their lines elsewhere.
- **What the game's code moves offline** that no rule has yet (etch#253): what

- **The capture driver's start state** compares the top-level windows only, so
  views inside the main menu's window are taken for the menu (etch#258).
- **The P2K playsets' captures**, other countries' views, and why a window is
  not reached (etch#258).

### After the offline classes (4 November 2026)

The report now has the **offline preview** (etch#299): each window with its
profile where it has one, else as the outline. It is the figure to read for
what a mod author sees without a game; the outline's own share leaves out the
profiles Etch ships, so the military tab's 555 rects counted against it though
a profile fixes them. At 1920×1080, on `eedace5` and after the PRs below
([docs/coverage-results.md](../coverage-results.md)):

| 1920×1080 | Offline preview: rects | Offline preview: visibility | Full (live) |
| --- | --- | --- | --- |
| vanilla | 95.2 → 96.0 % | 91.0 → 97.5 % | 41 |
| Anbennar alone | 95.6 → 96.4 % | 78.4 → 96.7 % | 39 |

**How far the visibility figures carry.** They are measured on the captures the
rules were drafted from. A rule that hides what every capture of a window hides
scores by construction there, and some windows rest on one or two views, so a
widget another country shows stays hidden until an author shows it by hand or a
live snapshot does. These figures say the views the survey saw are right; the
run on other countries below says how far they carry.
Bigger UI, the holdout, measures like vanilla (96.0 %, 97.7 %), but it shares
vanilla's game states, so it tests the mod's files, not other states.

The survey's "Pixel pass" falls from 5 to 3 of 61 views in vanilla at 1920×1080:
the two views still pass every widget, but they have a profile now, and a view
also needs the profile's prediction to hold. The drafted profile of
`countrydecisionsview` keeps `decisions_window` shown, which those two views
hide.

What is left, offline:

- **Text box heights**: mostly not a line break problem. The layout has the
  `.gui`'s placeholder and the game its own text, so the heights differ by
  content (`warscore_value`, `war_exhaustion`); a live snapshot gives the right

  dropped whole, with a notice. Anbennar's mission tree needed `"hidden": null`

and a live snapshot holds on every measure. The drafted visibility rules lose 4.0, 3.5 and 1.7

name widgets that decide it, not all the widgets that differed on the captures.

base game, with the selectors set to what the game shows. It does not reach Anbennar: Kobildzan,
also not used for the fixes, goes from 94.8 to 94.9 %. Its religion's own lists and an
elected ruler's court are the largest classes left, so Anbennar's profiles need the same work on a
country of their own. A claim that a fixed rule carries needs a country it was not fixed on.

[etch#308](https://github.com/happy-dwarf-team/etch/pull/308) came out of reading the survey for
etch#256: a sprite takes its last definition, not its first, as the game shows
`GFX_governing_capacity` and `GFX_choose_rivals_bg`.
[etch#309](https://github.com/happy-dwarf-team/etch/pull/309) lets a profile put a top-level
definition in a widget (`adopt`: the minimap's background and picture). The moves of etch#253 with
no setter in the code hold on both unseen sets, and the sizes the code sets that etch#256 lists are
the same in all four states seen, so they can become rules.

Three saves are not the game: 13 of France's 52 views, 8 of the Ottomans' 52 and 6 of Kobildzan's
49 could not be opened, and five planned sets, 1280×720 and the pixels were not reached. The 3.0.0 gate in section 3
still reads visibility from the live snapshot, which holds; the offline figures are reported.

## 6. Open points

- Views that Escape does not close (the outliner's options, the main menu's
  windows, the estates tab): the capture driver takes each in a game of its
  own (`run --max-starts`). Since etch#269 the crawler explores them one
  opening click per game; in the main menu it found the lobby's game options,
  find and options windows, and stopped when the lobby's back button restarted
  the game as a child process (now a `never` pattern). The menus' crawls are
  not done.
- Windows that remember their last tab open another view by the same key in
  one game; the crawler marks them and the capture takes them as a fresh game
  opens them.
- Views behind a confirmation (declaring war, sending a diplomat) are reached
  only up to the dialog; the corpus's `diplomacy-dialog` shows that one such
  dialog is reachable by a recipe. Decided: up to and including the dialog,
  never confirmed (section 2).
- Country-specific views (the emperor's, the Pope's controller's, a colonial
  nation's) need another country, which a console `tag` on a private copy of
  the save would give (Q7); not done in the first survey. Decided: in v3's
  survey, marked as taken with a game call (section 2).

## 7. Releases

Decided on 9 November 2026 (eu4-engine-lab#17, Q4, Q5 and Q15):

1. **2.7.0**: Compare with Live Game (section 4), after 2.6.0.
2. **Later 2.x releases**: the survey to the end (section 2), the profiles of
   Anbennar's own countries and rules read in the game's code, side by side.
3. **3.0.0**, once the gate of section 3 holds, with the media refresh as a
   step of that release.

Pixel fixes of the corpus's known deviations (etch#18) hold back no release.

## 8. Scope

What v3 takes from v2's "Not in v2" ([after-v2.md](after-v2.md), Q7):

- **In v3**: profiles for more windows, and for Anbennar's own countries
  (Kobildzan's offline visibility stays at 94.9 % after the fixes made on
  France, section 5).
- **Later**: a command that writes a profile skeleton; a headless mode for CI;
  code-set sprites and frames, tooltips and exporting a snapshot, which need a
  new `tongs.ui`.
- **Not planned**: a UI scale other than 1.0, editing in the preview, ironman
  saves, faithful offline rendering, checking 3840×2160 on a 4K screen.
- **The media refresh** is a step of the 3.0.0 release (section 7).

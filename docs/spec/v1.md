# Etch v1 specification

Etch v1 is the scope of release **1.0.0**: a Visual Studio Code extension that
previews Europa Universalis IV 1.37.5 interface mods while they are edited, with
hot reload, diagnostics and jump to source, through two preview backends behind
one preview. Releases before it are 0.x milestones (section 11).

This document says what v1 contains, in what order it is built and what is
left for later. It does not repeat the architecture: that lives in the ADRs
and in the resolutions of the
[wayfinder map](https://github.com/happy-dwarf-team/etch/issues/1), which this
document links. Terms are those of [GLOSSARY.md](../../GLOSSARY.md).

## 1. Target and principles

- **Game:** EU4 1.37.5, Steam, win64, on Windows only. The game host refuses
  any other `eu4.exe` hash; the offline renderer keeps working on another
  build and shows a warning that results are only checked against 1.37.5.
- **Both preview backends ship in 1.0.0:** the offline renderer (the default,
  no game needed) and the game host (the game itself draws the window).
- **Both show a layout preview.** The offline renderer draws the window
  skeleton and static localised text. The game host draws windows opened
  without a controller, so neither shows code-filled content.
- **Preview only.** Editing inside the preview is not in v1; the editor is
  VS Code's own text editor.
- **Speed first:** the budgets of section 7 are requirements, not targets.
- **Precision is measured, not claimed:** the precision corpus of ADR 0002.
- **No telemetry.** Etch sends nothing anywhere. The game's
  `CrashReporter.exe` is closed after its PID, path and creation time are
  checked, and no report is sent.

## 2. Editor features

### Preview and previewed window

- One preview in a webview beside the editor, opened by command or from the
  editor title of a `.gui` file. The preview is keyed on the file extension;
  Etch contributes no language id or grammar and coexists with CWTools and
  ParadoxCode ([etch#4](https://github.com/happy-dwarf-team/etch/issues/4)).
- The **previewed window** is the top-level window that contains the cursor
  in the active `.gui` editor. It can be pinned, so that the preview stays on
  that window while other files are edited.
- The preview follows the unsaved editor buffer on every change, as game text
  ([etch#15](https://github.com/happy-dwarf-team/etch/issues/15)).
- Textures (`.dds`, `.tga`) and fonts (`.fnt`) saved to disk in the mods are
  read again and redrawn; the game folder is watched only when its own files
  are edited. A file created or deleted loads the playset again. The preview
  reopens on the same window, pinned or not, after a window reload.
- A switch in the preview chooses the preview backend (offline renderer, game
  host) and the diff view (section 5).
- The render is transparent and is composited over a neutral background in the
  webview, the same for both backends.

### Widget outline and navigation

- **Widget outline:** a tree view of the previewed window's widgets from the
  extension's model, in file order.
- **Preview to source:** clicking a widget in the preview reveals its source
  line and selects it in the outline.
- **Source to preview:** moving the cursor in the source highlights the widget
  in the preview and in the outline.
- **Hover:** hovering a widget in the preview shows its path and rect.
- Outline and navigation come from the extension's model for both backends;
  the game host reads no widget tree (ADR 0003).

### Commands

- Open the preview.
- Switch the preview backend; toggle the diff view.
- Choose the preview resolution (section 6).
- Start and stop the game host.
- Remove the game host install.

### Settings

- `etch.gamePath`: the game folder. By default it is found through Steam's
  `libraryfolders.vdf`.
- `etch.playset`: the playset override, an ordered list of mods (names, or
  mod folders and descriptors) that replaces the default playset (section 8).
- `etch.language`: the localisation language, one of the game's languages,
  default `english`.
- `etch.previewResolution`: the preview resolution (section 6): `default`,
  `native` or a width × height such as `1920x1080`.

### Finding the game and the mods

- The game folder comes from `etch.gamePath`, else from Steam's library list.
- The playset's mods are resolved by the names in the workspace mod's
  descriptor `dependencies`, in the Workshop folder of app 236850 and in the
  `mod/` folder of the player's profile. Dependencies are followed
  transitively and load before the mods that name them; a name that is a
  Workshop id finds that item. A missing dependency of the workspace mod is a
  warning, one further down is information.
- The workspace mod is the installed mod whose folder holds the edited file,
  else the nearest `descriptor.mod` above it. The profile is the folder in the
  game's `userdir.txt` when it is not empty, else
  `Documents/Paradox Interactive/Europa Universalis IV`.
- `replace_path` hides the game's and earlier mods' files directly in that
  folder, not in its subfolders (not yet checked in the game).
- Etch only reads the player's game folder, mods and profile. It never writes
  to them; the game host writes only into its own game host install.

## 3. Offline renderer

Architecture: [ADR 0001](../adr/0001-typescript-renderer-host-layout-webgl2-webview.md).
Format facts: [etch#3](https://github.com/happy-dwarf-team/etch/issues/3).
First measurement:
[etch#9](https://github.com/happy-dwarf-team/etch/issues/9).

- **Windows:** any top-level window of a `.gui` file can be previewed.
- **Widgets:** all 23 widget kinds that vanilla 1.37.5 uses, drawn in the state
  the `.gui` defines. The test mods add no kinds.
- **Sprites:** all 8 sprite kinds that vanilla 1.37.5 defines in `spriteTypes`
  (`cursor_offset` there is not a sprite), frames as horizontal cells, and the
  shaders ADR 0001 lists plus `buttonstate_nodowneffect` (41 vanilla sprites),
  ported to GLSL with point or linear sampling from the shader table.
  `gui_rendertarget` and any unhandled shader draw with the default shader and
  produce a diagnostic. Layout sends the webview a draw list (`core`'s
  `draw-list.ts`), which the renderer draws premultiplied, so that its blending
  equals the game's over any background.
- **Textures:** DDS (BGRA8, RGB8, DXT1/3/5, under the classic or the DX10
  header) and TGA (16/24/32-bit, RLE, colour-mapped). DXT uploads compressed
  where S3TC is available and decodes on the CPU otherwise. A DXT image whose
  size is not a multiple of 4 is laid out and drawn at the size of its whole
  blocks, padding texels included, as the game does (etch#44; etch#30 had
  clamped it to the image).
- **Text:** the game's BMFont fonts with kerning, Windows-1252 glyphs, the
  rules found in etch#9 (a wrapped line keeps its trailing space) and in the
  corpus (etch#44): an instant text box is as tall as its lines plus its
  border; a centred line starts at `x + borderSize.x + ⌊width / 2⌋ −
  ⌊line / 2⌋`; button text sits on whole pixels by the same rule, centred
  vertically rounding half up; check boxes draw no `buttonText`.
  Localisation keys show their static localised text in the language of
  `etch.language`, with `§` colours and `£` icons drawn.
- **Layout** (etch#3, etch#9): `orientation` picks a point of the parent's
  box, `position` offsets the widget's top-left corner from it, and a widget
  without `orientation` anchors upper left. Full-screen windows take the screen
  size, windows do not clip their children, icons and buttons take their size
  from their sprite's frame. A scaled sprite is drawn at its exact scaled
  size with its bottom edge on a whole pixel, and the widget is that size
  rounded down; the game draws the largest of a sprite's `_huge` and `_large`
  variants that, measured from the top of the widget's window, ends on the
  screen, unless the widget's `.gui` picks its sprite by `if_resolution`
  (etch#44). Every widget of the previewed window is drawn,
  including sub-windows the game's code would hide. Layout gives the draw list
  and each widget's rect in paint order, for hover and the game host's crop.
- **Code-filled content** stays as the `.gui` defines it: lists, grids and
  overlapping-element boxes are empty, progress bars are empty, shields show
  their overlay without a flag, text is the file's own. `$…$` and `[…]`
  substitutions are shown literally, because the game's code fills them.
- **`if_resolution`** blocks are evaluated against the preview resolution.
- **Playset:** the same rule as the game host (section 8). A later mod's file
  wins over an earlier one, as in the game.
- **Budgets:** section 7.

## 4. Game host

Architecture: [ADR 0003](../adr/0003-extension-driven-game-host-in-private-install.md).
Verified live in [etch#21](https://github.com/happy-dwarf-team/etch/issues/21)
and [etch#22](https://github.com/happy-dwarf-team/etch/issues/22).
How the install and the process work, and what was measured:
[docs/game-host.md](../game-host.md).

- **Start:** on demand, at the first switch of the preview to the game host.
  It stops when the VS Code window closes, by command, or after 30 minutes
  without a game host preview. One game host per machine; a lock file tells a
  second VS Code window that it is taken.
- **Game host install:** a junction copy of the game in the extension's global
  storage, created on first use after one confirmation and removed by command.
  It holds the pinned builds of Anvil, `anvil-game`, Bellows and Etch's plugin
  (ADR 0004), whose hashes are checked before every start. The game starts with
  `-userdir=<private profile>/`. The private profile holds descriptors with
  absolute paths to the playset's mods and to the overlay mod, all owned DLC
  enabled, and the overlay mod loaded last.
- **Pipe:** the extension starts the game with a fresh session id in
  `ETCH_HOST_SESSION`, and Etch's plugin serves `\\.\pipe\etch-host-<id>`
  to the current user only: a handshake with the protocol version, then
  requests answered by id, and a ping with the frame counter
  ([docs/plugin-protocol.md](../plugin-protocol.md)).
- **State:** the main menu, no save. The game host is never minimised; it sits
  behind VS Code. Readiness is reported at `anvil-game.ready`.
- **Preview copy:** for the previewed window the extension writes the preview
  copy into the overlay mod by the rules of
  [etch#16](https://github.com/happy-dwarf-team/etch/issues/16), wrapped in
  the full-screen `<copy name>_backdrop` window of etch#22, as two copies:
  `etch_<file>.gui` over black and `etchw_<file>.gui` over white. The
  wrapped window's `position` takes the value of its `show_position`: nested,
  it stays at its `position` instead of animating there (etch#50). The game's
  `windowType` parser refuses an `eu3dialogtype` or a `shieldtype` inside a
  window, so a wrapped dialog is written as a `windowType` without its
  `shieldtype` children, each reported as information (etch#118). Laid over
  the screen behind it, the copy's image gives the original window's pixels
  within 1 per channel (H1 of etch#16, checked live in etch#119 and, for
  dialogs, etch#118; docs/game-host.md). The overlay mod ships the backdrop sprites and textures
  from the start, and `interface/etch_*.gui` and `etchw_*.gui` are cleared
  before each start.
- **Windows:** only top-level `windowType` and `eu3dialogtype` windows go to
  `window open`. Other top-level kinds get a diagnostic saying the game host
  cannot show them.
- **Jobs:** one job per change set, at most one in flight, later changes
  coalescing (the latest wins). A job closes the open wrapper, reloads both
  copies, opens the black wrapper and captures, then opens the white one and
  captures. A localisation change adds `reloadloc` before the open; a texture
  saved to disk adds `reloadtexture` after the black wrapper opens, because the
  game reloads only a texture it holds and closing the wrapper drops the
  window's textures (etch#117). The plugin calls the game's console dispatcher
  itself and turns the two crops into straight RGBA, which the webview reads
  from a file (docs/plugin-protocol.md, docs/game-host.md). The game host
  mounts the playset's mods before the base game, so a texture a mod overrides
  reaches it, at the start and after a save (etch#126).
- **Capture:** in `IDirect3DDevice9::Present`, a `StretchRect` of the crop
  rectangle (from the offline renderer's layout) into a small render target and
  a readback of only that. No full-frame readback.
- **Restart:** a `.gfx` or `.fnt` file of the playset saved, created or
  deleted on disk (the game reads them only when it starts), a new resolution,
  playset or language, a dead process, a hang (no answer to a ping, or a frame
  counter that stands still, for 10 s) or a console fault restarts the game
  host. During a restart the preview keeps the last image marked as stale, and
  changes coalesce into one restart: those that come before the old process is
  closed join it, later ones make one more (etch#51). After 3 crashes in 5
  minutes the game host stops, shows a diagnostic with the end of `error.log`
  and the file changed just before, and waits for a manual restart.
- **Closing:** a process is closed only after its PID, path and creation time
  match what Etch started; a lock file finds an orphan after a VS Code crash.
- **Diagnostics from the game:** the `error.log` lines a job caused and the
  console lines the game refused, on the original's lines where the game names
  a line of a copy, without a missing sprite the model already reports; and a
  warning when the game's own original of the window may not be the edited
  text (H6 of etch#16). docs/game-host.md describes the mapping (etch#52).
- **Known limitation:** a green FPS counter of unknown source is drawn in the
  top-right corner of the screen (60 × 20 pixels at 3440×1440); a crop that
  reaches that corner gets a warning.
- **Not in v1:** live game windows with code-filled content, widget tree reads,
  reloading the real HUD files.

## 5. Diff view

- The preview switches between the two backends' images of the previewed
  window, and can show the **diff view**: an overlay of the per-pixel
  difference between the offline renderer and the game host.
- Both images are straight RGBA of the same rect, so the comparison needs no
  extra capture.
- The **Diff** toggle in the preview and the *Toggle the Diff View* command
  turn it on while the preview shows the game host. Each game host image is
  compared with the offline renderer's draw list of the render its job
  answered, so an edit never compares a new render with an older image. The
  webview draws that list, reads it back as straight RGBA and compares it with
  the image within the crop (etch#54).
- A pixel is the same when every channel of the premultiplied colour and the
  alpha differs by at most 2, the precision corpus's tolerance; premultiplied,
  an almost transparent pixel's colour does not count. The picture shows the
  same pixels in dim grey, those both backends draw differently in red
  (brighter the larger the difference), those only the offline renderer draws
  in blue and those only the game host draws in yellow; the screen outside the
  crop is darker. A legend counts the differing pixels, and hovering a widget
  adds its share to the tip.
- Neither backend runs the game's code, but the game host draws each widget as
  the game leaves it without that code: nested windows the code hides and
  frames the code chooses differ (etch#53). The preview says so while the diff
  view shows, rather than masking them.
- The diff view is available only when both backends use the same resolution
  and playset; otherwise it is disabled with a note saying why. The resolution
  is the same when the preview resolution is the game host's (section 6); the
  playset when the game host's image was drawn with the preview's game folder,
  mods and language.
- A per-widget report stays the precision corpus's job; the diff view is a
  picture, not a verdict.

## 6. Resolutions and UI scale

- **Offline renderer:** the preview resolution is chosen from the six corpus
  resolutions (1280×720, 1366×768, 1600×900, 1680×1050, 1920×1080,
  3440×1440), the monitor's native resolution, or a custom width × height.
  The default is the resolution in the player's `settings.txt` (read only),
  else the monitor's native resolution. The choice is
  `etch.previewResolution`; a command and a button in the preview offer the
  choices. The native resolution is the monitor that shows the preview, in
  device pixels as the webview reports it, remembered for the next cold open;
  until it is known the preview uses 1920×1080. `settings.txt`
  (`graphics.size`, `graphics.game_ui_scale`) is read when the playset loads
  (etch#38).
- **Game host:** runs at the monitor's native resolution, borderless, as
  verified live, or windowed at a smaller corpus resolution. etch#18
  confirmed live that a windowed client area of each corpus size below
  3440×1440 captures pixel-exact. The size goes into the private profile's
  `pdx_settings.txt` (`windowed_resolution`, `display_mode`), which the game
  reads instead of `settings.txt` after its first start. Changing the game
  host's resolution restarts it. When the preview resolution differs from the
  game host's, the game host shows a note and the diff view is off.
- **UI scale:** 1.0 only. A `game_ui_scale` other than 1 in the player's
  settings produces an information diagnostic, shown as a notice in the
  preview, and the preview still lays out at 1.0.

## 7. Budgets

Measured on the maintainer's machine, from the unsaved editor buffer; not
timed in CI (ADR 0004).

| Playset | Warm reload | Cold open |
| --- | --- | --- |
| Vanilla | ≤ 50 ms for `countrydiplomacyview.gui` (148 KB) | ≤ 1 s |
| Anbennar + Proper 2K UI Enhanced + P2KE Patch - Anbennar | ≤ 50 ms for the playset's `topbar.gui` (347 KB, the patch's) | ≤ 2 s |

For scale: Anbennar has 61 `.gui` files (1.6 MB), 74 `.gfx` files and 59 MB of
English localisation against vanilla's 13.9 MB. In etch#9 the work of a warm
reload took about 6 ms for 148 KB and the 30 ms debounce dominated. The
preview therefore renders without a debounce: a change while it is idle
renders at once, and changes during a render coalesce into one more
(settled in etch#39).

The method and every result are in [docs/budgets.md](../budgets.md); the
vanilla measurement is the extension's test suite with `ETCH_GAME_PATH` set,
which fails when a budget is missed. A warm reload's budget is its p95 over
the measured edits; a cold open's is each one. Measured in etch#39 at
1920×1080 and 3440×1440 (three VS Code processes, three runs of 40 edits
each): warm reload median 6–7 ms, p95 8–14 ms; cold open 0.29–0.85 s, the
first preview of a process the slowest. The Anbennar playset, measured the same
way in etch#57 (six processes): warm reload of `topbar.gui` median 19–20 ms,
p95 22–24 ms; cold open 0.67–1.87 s, the first preview of a process
1.01–1.87 s.

The game host has no gated budget, because its timing depends on the game's
frame rate. Reported each release: the job time from a change to the image
(target ≤ 150 ms for files outside the HUD; etch#22 measured 63–73 ms for the
dual job) and the restart time to ready (13–15 s, 21 s on a new profile;
13–21 s in etch#53 with Bellows, docs/budgets.md). With the Anbennar playset
(etch#57) the game host gets ready about 40 s after a start and 36 s after a
restart, and a job of the patch's `countrydiplomacyview` takes 215–224 ms at
the median, its full-screen `topbar` 333–439 ms.

## 8. Playsets and mods v1 must handle

The playset is the workspace's mod plus the `dependencies` of its descriptor,
unless the playset override lists the mods in order. The maintainer's mods are
the first test cases:

| Playset | Precision (ADR 0002) | Functional requirement |
| --- | --- | --- |
| Vanilla, no mods | gates 1.0.0 | every window of section 9 |
| Vanilla + Proper 2K UI Enhanced | gates 1.0.0 | every window of section 9 |
| Anbennar + Proper 2K UI Enhanced + P2KE Patch - Anbennar | reported | every window the mods override opens in both backends without a crash, with diagnostics |

The Anbennar playset is the maintainer's: the Workshop items of Anbennar,
Proper 2K UI Enhanced and P2KE Patch - Anbennar, in that order, as the
corpus manifest pins them (etch#55). It replaced Proper 2K UI - Anbennar, a
stand-alone UI mod that is no longer maintained.

Dwarven Knowledge + DK-2KUI, a fourth playset on the map, was dropped from v1
([etch#56](https://github.com/happy-dwarf-team/etch/issues/56)): no one needs it
for now.

Known case: Anbennar's `countryreformview.gui`, as every Anbennar UI mod
has it, defines
`gov_view_reform_level_entry_4` twice at top level, which double-frees on a
reload ([etch#16](https://github.com/happy-dwarf-team/etch/issues/16)); Etch
reports it, and the preview copy never writes a top-level name twice.

## 9. Windows v1 must handle

- **Any top-level window** previews in the offline renderer; `windowType` and
  `eu3dialogtype` windows also in the game host.
- **The 11 vanilla corpus windows** of ADR 0002 and
  [etch#10](https://github.com/happy-dwarf-team/etch/issues/10) (main menu and
  lobby, HUD, Esc menu and message settings, court, diplomacy with one eu3
  dialog, province, ledger, settings, macro builder, estates, event) must pass
  the precision corpus and open in the game host with correct RGBA. The event
  window has no recipe yet
  ([etch#97](https://github.com/happy-dwarf-team/etch/issues/97)) and gates no
  release until it has one.
- Widget kinds the corpus does not cover (`buttonType`, `containerWindowType`,
  `extendedScrollbarType`, `gui_rendertarget`, `buttonstate_onlydisable`,
  `buttonstate_nodisable`) are drawn but not measured; the manifest lists them.

## 10. Diagnostics

All diagnostics come from the extension's model, except those marked as coming
from the game host. Severities decided on the map are given; the rest are set
in implementation.

| Diagnostic | Source |
| --- | --- |
| Missing sprite, font, texture or glyph; unchecked reference | ADR 0001, etch#4 |
| Unsupported DDS or TGA format; unhandled shader or `gui_rendertarget` | ADR 0001 |
| Game text differs from the editor text (Warning; Error on U+FFFD), with reopen or save-with-encoding quick fix | etch#15 |
| UTF-8 BOM in an interface file (Warning); localisation not in UTF-8 with BOM (Warning) | etch#15 |
| A top-level name defined twice in one file | etch#16 |
| Top-level window kind the game host cannot open | etch#16 |
| A dialog's `shieldtype` the preview copy leaves out (Information) | etch#118 |
| Other EU4 build than 1.37.5 (offline renderer) | section 1 |
| `game_ui_scale` other than 1 (Information) | section 6 |
| New `error.log` lines (game host) | ADR 0003 |
| The game's original of the window may not be the edited text (game host) | etch#16 |
| Crop reaches the FPS counter corner (game host) | etch#22 |
| Game host stopped after 3 crashes in 5 minutes, with the end of `error.log` | ADR 0003 |

## 11. Milestones and build order

Version numbers are indicative; release-please bumps the minor version on
`feat`. M2 and M3 can be built in parallel after M1: they touch different
packages.

1. **M0 Foundation** (no store release). The first pull request that adds code
   makes the repository public with CI, the team's rulesets and Anvil's merge
   settings (ADR 0004). It brings the pnpm workspace with `core`, `renderer`
   and `extension`, the `windows` and `conventional-title` checks,
   release-please, and `vsce package --target win32-x64` as a CI artifact.
2. **M1 Offline preview → 0.1.0**, the first store release, marked `preview`.
   Parser, model, layout, draw list, WebGL2 renderer, DDS/TGA/BMFont readers,
   game text, playset and game discovery, the previewed window, widget
   outline, navigation in both directions, the diagnostics of the extension's
   model, the resolution choice, `etch.language`, and the vanilla budgets.
3. **M2 Precision corpus → 0.2.0.** Manifest, the Tongs-scripted capture
   driver, the per-widget comparison, known deviations. Vanilla and Proper 2K
   UI Enhanced pass at the six corpus resolutions, all of which
   [etch#18](https://github.com/happy-dwarf-team/etch/issues/18) confirmed
   (etch#44; the event window waits for etch#97).
4. **M3 Game host → 0.3.0.** The C++ plugin in `plugin/`, the pin file and
   packaging of the pinned builds, the game host install, launch, pipe and
   handshake, the preview copy writer with the backdrop, jobs with dual
   capture, restart and watchdog, and the game host's diagnostics. H1 of
   etch#16, that the preview copy's pixels equal the original's, held live
   for three vanilla windows (etch#119), two dialogs (etch#118) and the 14
   root windows of the corpus views in both release playsets (etch#53).
5. **M4 Compare and scale → 0.4.0.** The diff view, the Anbennar playset in
   both backends, the Anbennar budgets, and its corpus report.
6. **1.0.0** when the criteria of section 12 hold. The `preview` flag is
   removed (etch#58).

## 12. Release criteria for 1.0.0

- **Precision:** the gate of ADR 0002. The vanilla playset passes at every
  corpus resolution (etch#18 confirmed all six), and the Proper 2K UI
  Enhanced playset passes. A new known deviation needs the maintainer's
  consent.
- **Budgets:** section 7, vanilla and Anbennar, measured locally.
- **Game host:** the 11 corpus windows of the vanilla and Proper 2K UI
  Enhanced playsets open in the game host with correct RGBA, and H1 holds:
  without it the game host does not ship in 1.0.0.
- **Large mods:** every window the Anbennar playset overrides opens in both
  backends without a crash.
- **CI:** the required checks of ADR 0004 are green on `main`.

How each criterion was met, checked in etch#58 against the records in the
repository (docs/budgets.md, docs/game-host.md, corpus/README.md):

| Criterion | Evidence |
| --- | --- |

## 13. Repository layout and conventions

```
packages/core       parser, model, layout, draw list, diagnostics (no vscode import)
packages/renderer   WebGL2 drawing
packages/extension  VS Code glue
packages/compare    the precision corpus's headless comparison (ADR 0002), never shipped
plugin/             the game host's Anvil plugin (C++, CMake, Anvil SDK)
corpus/             manifest and widget trees (no screenshots)
pins/               pinned builds: release tag, URL and SHA-256
docs/adr/           architecture decisions
docs/spec/          this specification
docs/budgets.md     how the budgets are measured, and the results
GLOSSARY.md         domain terms
```

- English in code, issues and documentation.
- Conventional Commits; the team's pull request rules: a draft pull request,
  ready and squash-merged once CI is green and review has no blocking points.
- Tooling and checks as ADR 0001 and ADR 0004 state.
- Every run of the game follows the EU4 engine lab's procedure: `eu4.exe`,
  saves and mods are never changed, and a process is closed only after its
  PID, path and creation time are checked.
- Research and prototypes go on `research/*` and `prototype/*` branches, which
  are pushed and never merged.
- Screenshots and other game assets never enter Git.

## 14. After v1

Not in v1, and not specified further here; [after-v1.md](after-v1.md) keeps
the list:

- **Sample data** for code-filled windows: format, who writes it, and how it
  stays honest against the game.
- **Editing in the preview** (drag, an attribute panel writing back to `.gui`).
- **Headless mode for CI:** diagnostics and precision checks without VS Code.
  `core` stays free of `vscode` so the mode remains possible.
- **Live game windows in the game host:** the game's own window instances with
  code-filled content, which need a recipe per window and a way to refill
  content after a reload.
- **Faithful offline rendering:** sprite, frame, font and colour per widget
  from the game (about 1–2 weeks of reverse engineering), only if pixel diffs
  prove too weak to diagnose corpus failures.
- **UI scale other than 1.0.**
